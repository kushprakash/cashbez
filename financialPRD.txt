============================================================
GLOBAL ARCHITECTURE RULES
============================================================

1. MULTI-TENANT DATA ISOLATION
--------------------------------

Every Financial business table MUST contain:

user_id
admin_id

This rule is mandatory.

Examples:

members
member_kycs
membership_plans
financial_settings
financial_plans

maturity_payments

financial_receipts
financial_audit_logs
daily_closings

All relevant tables must have user_id and admin_id.


2. DATA ISOLATION
-----------------

Every SELECT, INSERT, UPDATE and DELETE/soft-delete operation
must respect:

user_id
AND
admin_id

Never fetch a financial record only by ID.

Example:

WHERE id = ?
AND user_id = ?
AND admin_id = ?


3. CREATED/UPDATED BY
---------------------

Where applicable, financial tables should also maintain:

created_by
updated_by

Approval-related tables may maintain:

approved_by
approved_at


4. FINANCIAL RECORDS
--------------------

Never hard-delete financial transactions.

Transactions must be immutable.

If correction is required, use:

REVERSAL
ADJUSTMENT
CANCELLATION

with proper audit trail.


5. MONEY
--------

Use:

DECIMAL(18,2)

for monetary fields.

Do not use floating-point calculations for money.


6. DATABASE TRANSACTION
-----------------------

All financial operations must use database transactions.

Examples:

Account Opening
Deposit
Withdrawal
Interest Posting
Maturity
Premature Closure
Account Closure
Adjustment
Reversal


7. BACKEND IS AUTHORITATIVE
---------------------------

React frontend validation is only for user experience.

Every important business rule MUST also be validated/enforced
on Laravel backend.

Never trust:

plan_id
account_id
member_id
amount
interest_rate
charges
limits
KYC status

sent by frontend without backend verification.

============================================================
CORE BUSINESS RULE
============================================================

All financial services are Member ID based.

The operator/admin must select or enter Member ID before
creating any financial account.

Account opening flow:

Member ID
    ↓
Validate Member
    ↓
Fetch Member Data
    ↓
Select Financial Service
    ↓
Select Plan
    ↓
Enter Financial Details
    ↓
Validate Plan Rules
    ↓
Nominee
    ↓
Opening Amount / Installment
    ↓
Create Account


============================================================
KYC BUSINESS RULE
============================================================

DEFAULT:

KYC is NOT mandatory during account opening.

KYC IS mandatory during withdrawal/settlement according to
financial settings.

Default:

KYC at Account Opening = NO
KYC at Withdrawal = YES

Admin must be able to configure this from Financial Master.

Even if React tries to bypass KYC, Laravel backend must block
withdrawal when required KYC is not approved.
