40. DATA ISOLATION
============================================================

This is CRITICAL.

Agent A cannot access Agent B's:

- Member
- Saving Account
- DD Account
- RD Account
- FD Account
- MIS Account
- Deposit
- Withdrawal
- Collection
- Transaction
- Ledger
- Receipt
- KYC
- Maturity
- Report
- Commission
- Daily Closing

Every query must use:

user_id = authenticated user ID

AND

admin_id = authenticated admin ID

Do NOT trust these values from frontend.

============================================================
41. BAD QUERY EXAMPLE
============================================================

DO NOT USE:

FinancialAccount::find($accountId);

OR:

FinancialAccount::where('id', $accountId)->first();

============================================================
42. CORRECT QUERY LOGIC
============================================================

Use authenticated scope:

FinancialAccount
where user_id = authenticated user_id
where admin_id = authenticated admin_id
where id = requested account id

Same rule for every financial table.

45. AGENT API SECURITY
============================================================

Every API:

1. Authenticate user.
2. Check user status.
3. Check role.
4. Check permission.
5. Resolve authenticated user_id.
6. Resolve authenticated admin_id.
7. Apply scope.
8. Validate request.
9. Execute business logic.
10. Create audit where required.
11. Return only authorized data.

Never accept user_id/admin_id as trusted frontend parameters.

If received from frontend, ignore them or validate strictly against authenticated identity.
